## Findings

1. FAIL (the live terminal hides the hand-off). `server/stream.ts` `clip()` collapses every whitespace run to one space and cuts a line at `LINE_MAX` 400 chars. The Marketing final message is about 1,800 chars, so the live terminal shows "## Özet Lansman haftası … İçerik CLAUDE.md'deki … Görsel…" as one paragraph (s2-term.png): `## Değişen dosyalar`, the `## → design:` heading and the request body the user is about to approve never appear, and `## Özet` is not on its own line. The mock (F-chain) uses short pre-structured lines, so D-152's `white-space: pre-line` is invisible in live runs. The gate card carries the request, clamped to 3 lines. Owner: engine (keep newlines and give assistant text a higher cap, or keep the final message of a round whole).
2. WARN (over-delegation and scope creep on the child). The request asked for 5 visuals; Design produced no image (its `allowedTools` has no `pnpm shots`), instead edited product code (`src/content/shots.ts`, +56 lines of `LAUNCH-*` presets), wrote `mar-docs/LAUNCH_VISUALS.md`, spent 21 turns and $0.56 and opened an unrequested Design to QA gate for a spec, against "Önce kendin bitir". The chain cost $1.75 for a "kısa tut" prompt. Everything stayed inside `addDirs`, but a Marketing request led to a source edit nobody approved; this worktree was restored after the run (copies kept in the scratchpad `artifacts/`). Decision needed: may Design run `pnpm shots` (otherwise a request for images cannot succeed), and should a child be forbidden to open gates / edit `src/` unless asked. Owner: devops (island manifests, `fleet/CLAUDE.md`) with engine for a per-child "no further gates" flag.
3. WARN (both islands lost turns to a denied Bash). Marketing and Design each report a `;`-chained Bash command refused for permission, and the model records it as a lesson. Not a bridge defect; the island settings or CLAUDE.md could say one command per call. Owner: devops.
4. WARN (gate cards crowd the list at 960x540). F-gate (2 gates): the gates block ends at y 381 with the bottom of the Coding card cut, the first real row ("SOCIAL … 14 dk") is faded out and "+4 daha" is the only hint. F-fleet (2 gates plus search "shader"): the gate group fills the whole card and the island blocks shrink to one faded line "Coding … 1 canlı"; the typed filter has no visible effect. Nothing says the gate block scrolls. Owner: engine (cap the block at about 2 compact cards plus "+N kapı daha", or one-line prompts from 2 gates up).
5. WARN (the request text is truncated before the decision). Gate cards clamp the request to 3 lines with an ellipsis; the 5-item list and the constraint ("dış asset kullanılmasın") sit past the clamp, and the terminal does not show them either (finding 1). Owner: engine (expand on click or the full text in a title attribute).
6. WARN (the collapsed gate line expires while the chain is still the story). `collapseS` 300 s counts from `answeredAt`; here the answer came at 23:51:06 and the parent finished at about 23:54, so a few minutes later the island panel shows no trace of the chain and the only way back to the child is the strip in the terminal header. The live click on the line was not exercised for that reason (mock only). Owner: engine (keep the line while any session of the request is not done).
7. Note (cause not investigated). Scratch pages served by `pnpm dev` render titles in a Helvetica-like bold ("Marisland", panel titles) while the shots build renders Fredoka / Nunito. Probably the fonts were not applied yet at capture time on the dev server; the shots are unaffected.
8. Note. The in-flight disabled state of İzin ver could not be caught (ack under 150 ms); the error path (card re-enabled after a rejected command) was not exercised live because no rejected gate command occurred.
